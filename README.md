## Notes from the code archaeology desk

- **Fix the data before the architecture.** A permissions problem that looks like a new RBAC system may turn out to be one bad database query.
- **Migrate in slices.** Running old and new code side by side is usually safer than betting the product on a clean-slate rewrite.
- **Treat feature flags as an operating plan.** A 1% → 100% ramp needs pauses, monitoring, rollback criteria, and cleanup.
- **Keep pull requests small enough to understand.** Large changes still move faster when every step is boring to review.
